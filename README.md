# family_app

家庭エネルギーを可視化して家族のコミュニケーションを増やすアプリです

## 1. サービス概要

family_appは、家族それぞれの家庭内での貢献を見える化し、感謝やコミュニケーションのきっかけを作るアプリです。
家事や育児などの家庭内タスクを記録し、家族で事前に決めた役割割合と実際の実施状況をもとに「家庭エネルギー」を表示します。また、家庭への貢献によってカードを獲得でき、カードを通じて家族同士で感謝や会話を楽しむことができます。家事管理だけではなく、家族関係をより良くすることを目的としたサービスです。

## 2. 開発背景

私は大学で「ステップファミリーにおける家庭維持の工夫」をテーマに卒業論文を執筆しました。
インタビュー調査を行う中で、家庭を維持していくためには日常的なコミュニケーションや相互理解が重要であることを学びました。また、社会福祉士・精神保健福祉士として福祉現場で働く中で、家庭内の負担の偏りやコミュニケーション不足が様々な課題につながる場面を見てきました。家庭内には「見えない家事」と呼ばれる、周囲から認識されにくい作業が数多く存在します。その結果、自分ばかりが頑張っているという不満や、相手への感謝不足が生まれやすくなります。
そこで、家庭内での貢献を見える化し、感謝を伝え合うきっかけを作ることで、より良い家族関係の構築を支援したいと考え、このサービスを企画しました。

### 2-1. このサービスへの思い・作りたい理由

私は、離婚によって両親と一緒に生活できない子どもを少しでも減らしたいという思いを持っています。家庭内の問題は大きな出来事によって突然生じるのではなく、日々の小さなすれ違いや感謝不足の積み重ねによって生まれることも少なくありません。特に、家庭には周囲から見えにくい「見えない家事」が多く存在します。それらが十分に認識されないことで、不公平感や不満が生まれ、家族関係に影響を与えることがあります。
そこで本サービスでは、家族それぞれの貢献を見える化し、お互いの頑張りに気付きやすい環境を作りたいと考えました。
また、家事や育児を義務として管理するだけでは継続が難しいため、家庭への貢献によって可愛い部屋や世界が成長していくゲーム要素を取り入れています。
家族みんなで世界を育てながら自然とコミュニケーションが生まれ、感謝を伝え合える家庭を増やすことが、このサービスで実現したいことです。

## 3. 解決したい課題

私が最優先で解決したい課題は、見えない家事が認識されず、不公平感や孤独感が生まれてしまうことです。

私は大学でステップファミリーを対象にインタビュー調査を行う中で、良好な関係を維持している家庭には、お互いの立場や努力を認め合い、尊重する姿勢が共通して見られることを学びました。一方で、自分の思いや努力が相手に伝わらないことは、不満や孤独感につながりやすいことも分かりました。

このような課題はステップファミリーに限らず、一般家庭においても共通していると考えています。家族それぞれが家庭のために行動していても、その努力や気遣いが相手に伝わらなければ、「自分ばかりが頑張っている」「分かってもらえていない」という感情が生まれやすくなります。

特に、献立を考える、日用品の在庫を確認する、子どもの予定を管理するなどの見えない家事は周囲から認識されにくく、感謝や労いの言葉につながりにくい傾向があります。

本サービスでは、家庭内の貢献や見えない家事を可視化することで、家族がお互いの努力に気付きやすい環境を作る。これにより、「自分ばかりが頑張っている」という認識のずれを減らし、相手の貢献を自然に認識できるきっかけを提供したいと考えている。

### 6.1 MVP機能で実現したい価値

MVPでは、家庭内で行われている家事や見えない家事を記録し、家族全員がその内容を確認できる機能を実装する。
これにより、普段は認識されにくい家庭内の貢献を可視化し、家族がお互いの頑張りに気付くきっかけを作る。
また、家族ごとの役割割合と実際の実施状況から算出される「家庭エネルギー」を表示することで、家族全体で協力できている状況を共有し、家庭内での会話や振り返りにつなげることを目指す。

### 6.2 主な機能

### 家庭エネルギーの表示機能

家庭エネルギーは、家族ごとに事前に設定した役割割合と、実際の家事実施状況の一致度をもとに算出することを考えています。

例えば夫40%、妻40%、子ども20%と設定した場合、実際の家事実施割合がその設定に近いほど家庭エネルギーが高くなります。

また、本アプリにおける「安定」とは家事量の多さではなく、家族間で話し合って決めた役割分担が実践されている状態を指します。

表示方法については0〜100のゲージ形式を想定しており、数値だけでなくポン吉の表情や背景の変化によっても直感的に家庭の状態を把握できるようにしたいと考えています。

### 家庭エネルギー連動演出機能

家族ごとの役割割合と実際の家事実施状況から算出される「家庭エネルギー」に応じて、ポン吉の表情や部屋の背景を変化させる機能。家庭安定度が高いほど明るく賑やかな世界へ成長し、低い場合は少し寂しい雰囲気になることで、家庭の状態を直感的に把握できるようにする。
家庭エネルギーが低い場合でも、ユーザーにネガティブな印象を与えすぎないよう、部屋が荒れるような演出ではなく、ポン吉が段ボールハウスで暮らしているなど、親しみやユーモアのある表現を検討しています。サービス全体としては罰を与えるのではなく、家庭エネルギーの向上によって部屋や世界が成長するポジティブな体験を重視したいと考えています。

- 80〜100％：ポン吉が笑顔になり、部屋に植物や家具が増える
- 50〜79％：通常状態の部屋で生活する
- 0〜49％：ポン吉が段ボールハウスで暮らす

また、本機能は家族の優劣を評価することを目的としたものではなく、家族で家庭の状況を振り返り、お互いの頑張りや見えない家事に気付くきっかけを作ることを目的としています。

### ガチャ・ご褒美カード機能

家事や育児など家庭への貢献に応じてポイントを獲得し、そのポイントを使用してガチャを引ける機能。ガチャからは様々なご褒美カードを獲得でき、家族同士で感謝を伝えたり、一緒に楽しめる体験につなげたりすることで、家事や育児へのモチベーション向上と継続利用を促進する。ガチャからはレアリティごとに異なる「ご褒美カード」を獲得できます。

ガチャから獲得したご褒美カードはカード一覧に保存され、ユーザーは好きなタイミングで利用できます。カードを使用すると対象の家族へ通知が送られ、家事のお願いや家族同士のコミュニケーションのきっかけとして活用できます。

ご褒美カードは単なる家事代行券ではなく、家族間の感謝やコミュニケーションを生み出すことを目的としています。

カード例はノーマルの場合、ゴミ捨てカード、コロコロカード、洗濯物たたみカードなど、レアは洗面所掃除カード、食器洗いカード、お風呂掃除カードなど家事お願いに関するものに。スーパーレアやスペシャルスーパーレアは、リモコン王カード（その日の見たいテレビ番組を優先してもらえる、おやつリクエストカード、献立リクエストカード、スペシャルスーパーレアは、お姫様カード（1日お姫様扱いしてもらえる）など家族のコミュニケーションを増やす機能にします。

このようなカードを通じて、家事を「やらなければならないもの」として管理するだけでなく、「家族で協力すると楽しいことがある」という体験につなげたいと考えています。また、カードをきっかけに家族同士の会話や感謝の言葉が生まれることを目指しています。

## 7. このアプリの懸念点とその対策

### 懸念点1：ユーザーが利用を継続しない可能性がある**
 
### 何が問題になりそうか

本サービスでは家事や育児の実施記録を行う必要があるため、入力の手間を感じることで利用をやめてしまう可能性がある。

### なぜそう思うか

家事管理アプリは、記録すること自体が負担となり、継続利用につながらないケースがある。また、家庭内コミュニケーションの改善という効果は短期間では実感しにくく、利用目的を見失ってしまう可能性もある。

### そのために考えている対策

家庭エネルギーの可視化や部屋・世界の成長などのゲーム要素を取り入れ、家事記録を「管理」ではなく「楽しみ」に変えることで継続利用を促したいと考えている。また、家族全員で協力して世界を育てる仕組みにすることで、家族とのコミュニケーションを目的とした利用につなげたい。

### 懸念点2：家事の可視化によって家族間の対立が生じる可能性がある

### 何が問題になりそうか

家事や育児の実施状況を数値化することで、家族同士が貢献度を比較し、不満や対立につながる可能性がある。

### なぜそう思うか

家庭内で行われる家事や育児には、時間や労力だけでは測れない部分が多く存在する。そのため、単純な数値比較は「自分の頑張りが正しく評価されていない」という感情を生む可能性がある。

### そのために考えている対策

本サービスは家事の優劣や競争を目的とするものではなく、家族がお互いの頑張りに気付くきっかけを作ることを目的としている。そのため、ランキング機能ではなく家庭全体の状態を表す「家庭エネルギー」を採用し、家族全員で協力して成長を目指す設計を検討している。評価ではなく感謝やコミュニケーションにつながる体験を提供したいと考えている。

### 10-2. 技術選定の理由

RUNTEQのカリキュラムで学習しているRuby on Railsを用いて開発を行う。
Railsは認証機能やデータベース操作などの機能が充実しており、限られた開発期間の中でもサービス開発に集中しやすいと考えたため採用した。
また、本サービスは家族・家事・家事記録・家庭エネルギーなど複数のデータを管理する必要があり、Railsとの相性が良いと考えている。

### 今回チャレンジしたい点

- 家族グループ機能の実装
- 招待機能の実装
- 家庭エネルギーの算出ロジック
- 家事記録に応じたUI変化
- ゲーム要素を取り入れたユーザー体験の設計

### 不安な点

ゲーム要素や家庭エネルギーの計算ロジックなど、これまで実装経験のない機能が多く含まれるため、想定より開発工数が増加する可能性がある。
そのため、まずはMVPとして家族管理機能・家事記録機能・家庭エネルギー表示機能の完成を優先し、その後段階的にゲーム要素を追加していく方針とする。
そのため、まずはMVPとして家族管理機能・家事記録機能・家庭エネルギー表示機能の完成を優先し、その後段階的にゲーム要素を追加していく方針とする。

## 10-3.キャッチアップ不足の懸念

現時点では、家事記録に応じた動的なUI変更やゲーム要素の実装について知識不足があるため、調査や検証に時間を要する可能性がある。
また、開発初期は機能ごとの実装工数を正確に見積もることが難しいため、MVPで必要な機能を明確に定義し、優先順位をつけながら開発を進める。
ReactやNext.jsなどの技術については興味を持っているが、卒業制作期間中はRuby on Railsを中心に開発を進め、必要に応じて導入を検討する。
